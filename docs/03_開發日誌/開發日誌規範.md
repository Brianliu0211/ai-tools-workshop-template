# 📓 開發日誌規範

## 1. 放哪裡

| 日誌內容 | 位置 |
| :--- | :--- |
| 某個工具的開發 | 該工具內 `NN_工具名/docs/開發日誌/YYYY-MM/` |
| 工坊規則、公共規範的調整 | 本資料夾 `docs/03_開發日誌/YYYY-MM/` |
| 同時改到多個工具 | 寫一篇放在工坊本資料夾即可，不在各工具重複寫 |

- 日誌跟著所屬的 git repo 走：工具日誌進工具的 repo，工坊日誌進工坊 repo。

## 2. 檔名

- `YYYYMMDD_功能標題.md`，標題簡短、描述功能。
- 同日多篇用不同功能標題區分，**不使用流水號**。

## 3. 內容範本

開頭的四面向欄位讓日誌自動接上 Obsidian 開發網，填寫規則見 [知識庫連結規範.md](../00_公共規格/知識庫連結規範.md)。

```markdown
---
date: YYYY-MM-DD
type: feat            # feat / fix / refactor / docs / chore
tools: ["[[工具名]]"]
components: ["[[元件名]]"]
tech: ["[[技術名]]"]
problems: []          # 沒有就留空陣列
---
# 開發日誌：YYYYMMDD_功能標題

## 1. 任務與目標
- **涉及工具**：`NN_工具名`（可多個；工坊規範調整則寫「工坊」）
- **核心目標**：條列本次要解決的問題

## 2. 核心實作內容
- 依功能分點說明改了什麼、為什麼這樣做，附上相關檔名

## 3. 完工檢查
- 對照 [新工具建立流程.md](../00_公共規格/新工具建立流程.md) 完工檢查清單，列出本次相關項目結果
- 未完成或略過的項目要明確寫出原因

## 4. [Handoff 狀態條言]
- **目前狀態**：做到哪裡、哪些已測試
- **關鍵決策**：本次的取捨與理由
- **建議下一步**：下次接手應從哪裡開始
```

## 4. 學習筆記

不是開發某個工具，而是**學新工具、裝環境、搞懂一個概念**時寫學習筆記（判斷方式見 [AGENTS.md](../../.agents/AGENTS.md) 第 3 節「東西放哪裡」）。

- **位置**：工坊 `docs/04_學習筆記/YYYY-MM/`，進工坊 repo。
- **檔名**：`YYYYMMDD_主題.md`，例如 `20260115_本機AI環境.md`。
- **同一主題追加、不另開新篇**：寫之前先搜尋 `docs/04_學習筆記/` 有沒有同主題的筆記；有就追加在原篇對應段落（新內容標日期，例如「（2026-02-03 補）」），沒有才新開。一次對話問了好幾個相關問題，合成一篇分段整理，不要一題一篇。
- **第 1 段必寫起因**：「為什麼要學」要寫出當時在做什麼、怎麼問到這裡（例如「想整理收藏的網站，發現缺一個命令列工具，才問到怎麼安裝」），讓日後沒有對話前後文也看得懂這篇從哪來。
- **與想法收件匣的關係**：想法開始動手學之後，在收件匣該則加上學習筆記的連結。

```markdown
---
date: YYYY-MM-DD
type: learn
tools: []             # 跟某工具有關才填
components: []
tech: ["[[技術名]]"]
problems: []
---
# 學習筆記：YYYYMMDD_主題

## 1. 為什麼要學
- 想解決什麼問題、從哪個想法來的

## 2. 學到的概念
- 用自己聽得懂的話寫（可用比喻），不抄官方說明

## 3. 實際操作步驟
- 照著做就能重來一遍（換電腦、重灌時用）；附指令與設定值

## 4. 踩到的坑
- 跟預期不一樣的地方、查證後更正的資訊

## 5. 我的判斷
- 最後選了什麼、為什麼；還有哪些選項沒選

## 6. 下一步
```
